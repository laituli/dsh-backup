# 运维 · 恢复备份（三条路径怎么选）

## 决策表

| 你的处境 | 用什么 | 会发生什么 |
|---|---|---|
| 宿主正常、面板能点，恢复后你愿意自己重启 | **面板恢复**（运维 → 备份 → 恢复） | 宿主运行中：先把当前 `DSH_HOME` 挪旁 + 快照，再写入归档；完成后按交接卡重启 |
| 恢复的是“当前正在用的这套数据”，想避免占用/半途写入，或需要停机窗口 | **部署期恢复**（确认弹窗勾 deploy + 延时） | 武装一个孤儿执行器：宿主空闲 → 延时 → 停宿主 → 挪旁 → 恢复；武装后可停（删 `.abort` 文件） |
| 宿主起不来、面板打不开 | **救援通道**（`rescue restore` / 双击「点我恢复」） | 不需要宿主：直接校验 + 恢复，最适合灾时 |
| 只想装/升级插件 | 见「重装 / 安装」 | 不碰数据 |

## 硬前提

1. **DSH_HOME 的末级目录名要与归档一致**（默认 `~/.dsh` 天然满足）；不一致会被安全校验拒绝。
2. **恢复后必须重启宿主**（整包/类型 merge 都要），且启动命令要带同样的 `DSH_HOME` 与 cwd。
3. **跨机恢复**只给提醒、不自动改绝对路径：`settings.yaml`、`cordis*.yml`、`storages/workspace.json`、
   会话 header 里的 `cwd` 都可能是旧机器的值。
4. `profiles/*/node_modules` **不进归档**：先重装依赖（`pnpm install`），再启动——顺序不能反。

## 面板给出的两条可复制指令

- **① 停止旧宿主**：`node <备份目录>/rescue.mjs stop --web-port <端口>`（幂等：没在跑就跳过）
- **② 启动新宿主**：宿主自身启动命令的原样复现（含 profile）
- 部署期恢复另给 **③ 手动停机恢复**：自动执行器没生效时的等价指令

> 为什么优先用「备份目录里的 rescue 副本」：它每次备份刷新、自包含；灾时 profile/插件可能已损坏，
> 而这份副本还在。
